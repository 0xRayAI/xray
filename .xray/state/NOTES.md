## Lens, the job

Call it a lens. One lens for one plane. It is the page you read instead of the code.

The idea is three steps. The lens stands for one plane. It is a glimpse, so you do not read that plane's code again. The AI looking at it decides whether the plane needs a deeper dive, and that dive is a facet, a feat, or a fix. Then it does the work or queues it. The lens does not make that call. The AI already knows where it came from and why it opened the lens.

If the code for a plane exists and there is no lens, build the lens from the code. If the lens is missing something the code already has, fill that in. If the project has no stamped plate yet, stamp it. Do not invent a line the code does not have.

No separate worker builds lenses ahead of time. The AI who came to do the work does it on the way in: create or fill the lens, stamp any plate that is missing, then do the job. The first visit is the build. The next visit finds the lens and does not read the whole plane again.

That check sits in the tool path, the same way the other organs do. Before the AI calls explorer or researcher, or goes off to research the code, the tool is stopped and the lens is handed back. The AI then decides if it still needs to research. The point is to put it on the right path immediately, not after a long search.

The extra machinery is not this job. The six outer names, the match file, and a hold that stops a tool are not the glimpse and they are not the decision. A blank line is blank only when the code has nothing to put there. A feat is the AI's decision when the lens is already full and it still wants more.
