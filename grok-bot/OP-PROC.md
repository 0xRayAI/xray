# Operating procedure

How the roles work. Read this first. Who you are, where you post, and which repos you may push live in `house/`. If that folder is missing, start from `templates/house/`. Name your seats anything. [Example house (names are illustrative)](templates/house/EXAMPLE.md). Every term here is defined in the [lexicon](LEXICON.md); if they disagree, the lexicon wins.

- **Two loops.** All work lives in GitHub: one issue or PR per task, on its own branch and worktree, never on main. Anyone outside the fleet, such as Arch1, another fleet or a maintainer, is reached only by issue, PR or comment, @-mentioning who acts next. That is the outer loop, and it is what becomes cards, nudges and tripwire. Inside the fleet, seats wake each other with direct messages, and each message points to that issue, PR or packet. A direct message with no GitHub record is not work. To reach someone outside the fleet, @-mention them in an issue, PR or comment. The collector turns that comment into their inbox line, which is what wakes them, so never post to their inbox separately. The mention must be their real GitHub login: before @-mentioning anyone, look up their login at the Bifrost server's `GET /routing`, never from memory (`bifrost init --check` fails a nickname-only route).
- **Coordinator never:** deploy, publish a package, change production, launch a cloud agent, post in public, spend, or merge. A seat never merges code it wrote: the implementer writes code and opens PRs; the publisher keeps continuity, gates and the merge chain.
- **Roles:** The seat field is the role, not a personal name. Code, pull requests, cloud work, deploys, and package publish = **implementer**. Shipping after review = **publisher**. Ship, live, security, and identity review = **reviewer** (a short note, no merge). Public posts, listings, and audio are optional **specialists**. The coordinator is also called CoS. Money, credentials, and deletes = the **human owner**. **New seat before any ship work:** clear role description; fasten suit (mill+inspect) with inspect receipt on disk (`ok: true`, suit fastened, costume false); orientation + KB (role card, scope, grow mem from receipts); seat reads KT/orientation and acks before first carded job; if role was announced publicly, standing ROLE board card matching the announcement; CoS cards first work — seat quiet until carded; a new seat starts with only its profile + new-hire packet. A chat packet alone is not a suit.
- **Card:** one GitHub issue or pull request (`repo#number`). Fields: title, url, owner seat, stage (`open` > `review` > `fix` > `merge` > `retest` > `done`), state (`live`, `parked`, or `closed`). A chat ping is not a card. A card may carry `start_after`, an ISO time with a Chicago offset (`America/Chicago`, `-05:00` or `-06:00`). Until that time the card stays parked: no nudge, no tripwire, no empty-board pull. At that time the server wakes the owning seat through the normal inbox wake. Set it with `live-inbox <seat> --card owner/repo#n --start-after <ISO>`, or with a GitHub comment whose first line is `Start after: <ISO>`. The command wins while it is stored. The date is on disk, so a restart still honors it.
- **Packet:** the card's eight fields — goal, constraints, path, acceptance, gates, evidence, next owner, escalate. `gates:` is set by the implementer; the reviewer may raise it, never lower it; it locks once review starts. They come from a `## Packet` block in the issue or pull request body, or from one line. Each field is at most 200 characters, and links are allowlisted. If acceptance or next owner is missing, the card is amber with a `no packet` badge. Evidence fills from the latest beat.
- **Handoff = packet + wake** (the inner loop of **Two loops**). The seat that owes it runs `live-inbox <seat> --handoff <to> --pr <owner/repo#n> --kind <ready|critic_fail|live_pass|merge|ci_fail> --sha <head>`. That posts one inbox packet. The seat sends the printed line as a 1:1. A **room post** is never a handoff and never a wake. Seats may not ack in rooms (they might or might not), so a room receipt cannot be relied on. A room post that names the next seat does not discharge the handoff, including a CoS room post. If the packet is missing for `NUDGE_L1_S`, the card is flagged `handoff missing` and the owing seat is nudged L1, then L2, then L3. The CoS role is woken at L3. The server does not post the packet. A webhook is a doorbell after the packet exists. It does not replace the 1:1. A non-empty read is the work. A tracked packet moves `sent` → `delivered` → `woken` → `acked`, and is `overdue` past `NUDGE_L1_S`. Kinds on a tracked packet are `dispatch`, `ready`, `packet`, `critic_fail`, `needs_human`, or a blocker (`needs_human`, or `to` = `WORK_HUMAN_TO` on the `WORK_HUMAN_LANE` lane). Handoff kinds are `ready`, `critic_fail`, `live_pass`, `merge`, and `ci_fail`. A line that only names `from` is not a packet.
- **Activity key.** `POST /activity` uses that seat's `SEAT_KEYS` entry. The seat posts only as itself (its id, alias, or `SEAT_DISPLAY_NAMES` label). A cross-seat `seat` is `403` `seat mismatch`. Builder still uses its GitHub App token.
- **Working.** Three writers, and they stack. An open turn (`applyStoredActivity`) expires after `LIVE_TURN_OPEN_MIN` (default 20) if the ack never comes. A turn `end` or an ack clears working. The turn end still clears after `TURN_OPEN_MS`. The drop clears a mark at or before the end. A mark newer than the end stays only while it is inside `TURN_OPEN_MS` (20 minutes, `LIVE_TURN_OPEN_MIN`), then it expires. Newer GitHub marks expire at 20 minutes. A running cloud agent stays. A mark with no time stays. A woken packet or a running agent (`applyTrackWorking`) sets the chip `working_on`. A GitHub comment, review, PR opened or pushed, or issue event (`applyGithubWorking`) marks the actor's seat working for that same window, with `working_on` = `repo#number`. The card clock ignores CI and `pr_commit` on both sides it compares. A card-worthy event on a closed card is not a stall. A `pr_open` the board has not carded still is. The actor login maps through `inbox-roles.json`, `fleet-nodes.json` / `LIVE_NODE_MAP`, `LIVE_GH_SEATS`, and `git:<seat>` (`SEAT_GIT_NAMES`). A cloud agent maps through `SEAT_AGENT_MAP` or a `bc-` id in the branch or comment. `critic0x[bot]` is critic. `forge0x1[bot]` is forge. `CURSOR_WEBHOOK_SECRET` (32 characters or more) signs `POST /cursor/webhook`; shorter or unset, the launch does not register one. The chain is `house/live/docs/work-tracking.md`. A close or a merge of the item in `working_on` clears that chip on the seat and in `fleet.working`. The seat can stay working. `POST /activity/ingest` is the box-uploader exception to the per-seat pin (`house/live/docs/activity-upload.md`).
- **Beat:** one real event — a pull request opened or pushed, a review APPROVED (Reviewer PASS) or CHANGES_REQUESTED (Reviewer FAIL), a merge, a merge-queue tick, an owner message, a fleet seat's comment, a blocker, or a finished deploy (deploy, deploy_fail). CI stays on the card and is not board traffic. A draft parks at once. A live pull request with no beat for 72 hours parks. A reopen clears closed and stop. A merge or a close sends an info line to the author's seat. burst-live is the board, never a node. A watcher run whose start and end fall in the same second is never a beat. An idle loop on parked work is theater. The station is the survival strip. Wake on a PR, a person, or a compact.
- **Routing.** Every seat has a route in `inbox-roles.json`, and every route @-mentions the seat's real GitHub login, not only its nickname. The routing map lists each seat once with that login and its nicknames as aliases; the server resolves every login on GitHub and refuses one that does not resolve. Bifrost does not work without it: `bifrost init` writes it, `bifrost init --check` fails on a missing or nickname-only route.
- **Ack.** A seat acks an inbox line with `live-inbox <seat> --ack <id>` after it handles the line. `live-inbox <seat> --ack stale` lists lines with a close or merge event, or a closed or done card, and does not ack them until `--apply`. A missing card stays, and so does an old handoff whose card is still live. `--upto <id>` acks the stored prefix through that id, including live lines. `--ack all` acks every open line at once. An ack is a plain seat-key call and never raises an approval card. Every seat runs the export line in `templates/house/fleet/WAKE-ROUTINE.md` before any `live-inbox` command. It puts the install folder on `PATH` and sets `LIVE_URL`, `SEAT_KEYS_DIR` and `LIVE_CURSORS`. `live-inbox` never guesses a missing one: it exits 2 and names it. Use the installed copy, never a stale one in `/tmp`.
- **Tripwire.** When nothing has moved for the trip window, the tripwire starts the timed run once per window: an empty board wakes the coordinator to pull the next work; a stalled board wakes each seat with open work.
- **Nudge.** A live card with no beat: L1 goes to the next owner, or else the card owner. L2 goes to the CoS role. L3 repeats to the L1 seat, and the CoS role is woken once to reassign. An unacked inbox line steps L1, L2, and L3 on that same seat, and the CoS role is woken at L3. A missing handoff nudges the owing seat at L1, then L2, then L3, and the CoS role is woken once at L3. The owner fixes its own card; the CoS role owns the board. A `Start after:` comment counts only from the card owner or a fleet seat. A stranger's comment is ignored. A time more than 30 days after now is ignored. The card field `merged_by` is the merger, never the author.
- **Names.** Docs and plates use the current seat, login and tool names. `bifrost check` greps them for the stale ones.
- **Runbooks.** Each seat's how-to lives in the pack, not in a seat's memory: [implementer](runbooks/IMPLEMENTER.md), [coordinator](runbooks/COORDINATOR.md), [ship](runbooks/SHIP.md), [critic (`bifrost check`)](runbooks/CRITIC.md).

Packet template:

```
## Packet
- goal:
- constraints:
- path:
- acceptance:
- gates:
- evidence:
- next owner:
- escalate:
```

One line, when the job is short: `goal: … · constraints: … · path: … · acceptance: … · gates: … · evidence: … · next owner: … · escalate: …`
- **Done** = a live receipt (a URL, a registry view, a GitHub Release URL, or reviewer PASS). Green CI is only gate A. Gates: A CI green, B the pack installs, C the docs match, D published and proven live (fresh install and upgrade, annotated tag pushed, GitHub Release so Latest flips). A pushed tag alone is FAIL for gate D. **Floor:** gates A and C on every merge. B and D are set per PR by scope (subsystem, module, component touched) in the packet's `gates:` field: does it work across all TUI environments, and are the docs updated throughout. Per-scope criteria: set per PR for now. TUI environments: Cursor, Grok CLI, Hermes, OpenCode, OpenClaw. **Gate B runs on the owner's machine** (seat computers lack these environments): when `gates:` calls for B, the packed tarball plus a per-environment checklist (git and non-git folder, temp home, run and update the `.cjs`/`.mjs` files for each TUI environment) is run either by a seat through owner-approved local tool steps, or handed to the deep-review seat in a PR comment when it runs locally there. Cloud runs (cloud agents, cloud deep review) never satisfy B. Whoever runs it posts the receipt; B stays unverified until that receipt exists. A chat "looks good" is not done.
- **Review:** Light and Normal = the reviewer's Light PASS + CI before merge (green CI alone never merges). Strict only for ship, live, security, or identity. Doc copies = Normal. Label every finding blocker, nit, or unverified. The first review lists every blocker; a re-review checks only those; nits never start a round. One fix round per PR; a second FAIL goes to the human owner. **Hotfix bypass:** a broken production change ships at once. Forge writes the fix with a regression test in a cloud agent, merges as forge0x1, and the cloud agent deploys once: no CI wait, no critic review before merge, no rollback. Critic does one live pass on production after the deploy; a failed pass is another hotfix ([steps](runbooks/SHIP.md#hotfix)). Merge needs the reviewer PASS posted as a GitHub App review on the PR; a chat PASS or a personal-account approval never counts.
- **Disk, not chat.** After a compact, and on every wake, read the station, then the board, then memory, then resume the same role. Don't start a second copy. Read `house/WAVEBOARD.md` and `house/ATTENTION_STATE.md` first; if missing, use `templates/house/`. No board file means the board is theater.
- **You first.** The human's direct message beats bot pings. Reply first. An open inbox line is not a ping: a non-empty inbox for this seat is the job. Answer the human in one line, then do the open lines before anything else. Anything a human reads should land in about three seconds. **Public voice** (account, spacing, replies) is a placeholder in `house/`. Don't open with "Locked:". If you say you will share something, do it the same turn. **Quiet** when someone only repeats CLOSED, MERGED, or LIVE.
- **Money and ship:** Ask first before you publish, change production, pay, touch secrets, or delete — unless `house/` names an exception. Git push only to repos named in `house/`. A "merge deploys this repo" exception is named there, one repo at a time.
