# Seat wake routine (template)

The prompt each seat installs as its webhook-triggered Bifrost inbox wake routine (inbox docs: `house/live/docs/inbox.md` in the repo). Copy the commands below as they are. Replace `<seat>` only. Set `SEAT_KEYS_DIR`, `LIVE_CURSORS` and `LIVE_URL` as folder or URL names only, never a key value. These commands post straight to the board with the seat's own key. The box pusher is not in this routine.

This routine is the Bifrost inbox wake, and it sets `LIVE_URL`. A seat with no `LIVE_URL` does not use it: that seat reads and writes `house/WAVEBOARD.md`.

Env first, on every turn, in the same shell as the commands below. `live-inbox` is installed at `$HOME/.burst/bin/live-inbox` (fetched from `house/live/tools/live-inbox` on main); a box that installs it elsewhere sets `LIVE_INBOX_BIN` to that folder (on the forge box, `/home/box/burst-run/bin`). `live-inbox` itself never guesses: a missing `LIVE_URL`, `SEAT_KEYS_DIR` or `LIVE_CURSORS` exits 2 and names it. The export block below fills those with the burst-live fleet's defaults, so any other board exports its own `LIVE_URL`, `SEAT_KEYS_DIR` and `LIVE_CURSORS` on the line before the block.

```bash
export PATH="${LIVE_INBOX_BIN:-$HOME/.burst/bin}:$PATH"
# default board is the public Bifrost URL; another board sets all three before this block
export LIVE_URL="${LIVE_URL:-https://bifrost.0xray.dev}"
export SEAT_KEYS_DIR="${SEAT_KEYS_DIR:-$HOME/.burst/seat-keys}"
export LIVE_CURSORS="${LIVE_CURSORS:-$HOME/.burst/cursors}"
export WAKE_RUN="${WAKE_RUN:-$$}"
trap 'live-inbox <seat> --turn end --tag wake; live-inbox <seat> --release' EXIT
live-inbox <seat>
```

A real owner-chat source is future work. This is the line: On every owner message, first run `live-inbox <seat> --prompt --from owner --note "<gist>"`; after handling any inbox line (in chat or on a wake), ack it right away with `live-inbox <seat> --ack <id>` (or `--ack all` once everything open is handled); when you launch or resume a cloud agent run `live-inbox <seat> --turn start --tag "bc-<first8> <track>"`; when it finishes or is cancelled run `live-inbox <seat> --turn end --tag "bc-<first8>"`. No exceptions for short turns.

0. List the open inbox first with the command above (`live-inbox <seat>`). That export sets `LIVE_URL` and `LIVE_CURSORS` (`$HOME/.burst/cursors`). `live-inbox` writes this seat's cursor at `$LIVE_CURSORS/<seat>.txt`. On an owner message (a 1:1 or a room), before an empty inbox stops the turn, run `live-inbox <seat> --prompt --from owner --note "<gist>"` once, even when that read is empty or every line is a repeat, and add `--room <name>` when the message was in a room. After handling any inbox line, ack it with `live-inbox <seat> --ack <id>` or `--ack all`. When you launch or resume a cloud agent run `live-inbox <seat> --turn start --tag "bc-<first8> <track>"`; when it finishes or is cancelled run `live-inbox <seat> --turn end --tag "bc-<first8>"`. This webhook wake then runs `live-inbox <seat> --turn start --tag wake`. The tool posts no turn start and posts no turn end when another live wake of this seat already holds the claim, and only that claim's owner token may release it or post its turn end: that run prints nothing and does not ack the first run's lines. Before any ack, do step 1 and read the station ticket. Decide a repeat with a cheap handled-record read, `live-inbox <seat> --repeat --pr <owner/repo#n> --sha <head> --kind <kind>`, which checks the per-seat cursor key `repo#number|sha|kind`. The claim is not that record. Ack a line with `live-inbox <seat> --ack <id>` only when `--repeat` exits 0. A new head is not a repeat and is not acked. After the line is handled, record it with `live-inbox <seat> --remember --pr <owner/repo#n> --sha <head> --kind <kind>`. A line that says the seat is still waiting gets one reply, is acked with `live-inbox <seat> --ack <id>`, and does not stop a newer line. A still-waiting stop exits through the shell trap. The trap posts turn end and then release on any exit, including a crash, so the claim does not hide the lines while the pid is still alive and the turn still closes. A duplicate or a still-waiting delivery is a quick check: the wake does not launch or resume a cloud agent for it. A new line keeps the full boot read below. An early return still runs step 7.
1. Boot read, every turn (a compaction is a wake). Grok Bot wakes never run `.cursor` hooks, so this step is the boot hook. Read `.xray/state/STATION.md` (the station ticket; never hand-edit it), then `.xray/state/NOTES.md` (the working page), then this seat's Bifrost cards (`GET /cards` on `LIVE_URL`), and resume the same role and job. If STATION.md is missing, or its `Fresh:` line names an older package than `node_modules/0xray/package.json`, run `npx 0xray wear` once and read it again; if it's still stale, append one line to NOTES.md and go on. If NOTES.md is missing, create it with `Point:`, `Open:`, `Learned:` and `Next cut:` lines (no secrets) before step 2. This wake is station Full: also read the file named by the HOUSE.md `OP-PROC:` line, the newest two NOTES entries, `house/fleet/TRACKS.md`, open board cards, and the STATION `Skills:` line. Light, on an owner message that is not a summary, a wake, or a gate, is the prompt plus STATION.md and does not read the pack.
2. Read your inbox: `live-inbox <seat>`. A non-empty read is the work. An empty read with nothing owed is a quiet wake: skip steps 3 to 6 and go straight to step 7. No room post, no NOTES.md write.
3. Handle each open line on its GitHub issue or PR, then ack it: `live-inbox <seat> --ack <id>`. Closed or merged lines are `live-inbox <seat> --ack stale` and then `--apply`. `--upto <id>` acks the stored prefix through that id, including live lines. `--ack all` acks every open line. A missing card, and an old handoff on a live card, stay until `--ack <id>`. When this seat owes a handoff, and this seat is not the CoS seat, run `live-inbox <seat> --handoff <to> --pr <owner/repo#n> --kind <ready|critic_fail|live_pass|merge|ci_fail> --sha <head>` and send the printed line as a 1:1. The CoS seat does not post a handoff. The CoS seat only acks a dev line and sends no message about it. The CoS seat acts only on next-wave planning, burn pacing, H-lane and Dist packets, and seat onboarding. A room post is never a handoff and never a wake: seats may not ack in a room, so a room receipt cannot be relied on.
4. A webhook wake never launches or resumes a cloud agent. It quick-checks the inbox and exits on a duplicate or a still-waiting delivery, records the event, and hands off to the owner's chat (forge for builds, critic for reviews) with a seat message pointing at the card. Only the owner's persistent chat launches or resumes a cloud agent. That chat reads `GET /cards` first. It does not launch or resume when the card id is missing. A missing id is not a launch. The cloud agent pushes its branch only. The seat App opens the pull request. The server attaches that branch and that pull request to the same card. The activity line gains no new field. Write the cloud id to `house/fleet/TRACKS.md` in the launch step. On the way out write the card metadata: title, url, owner seat, stage, and state. A cloud agent pushes its branch only and never opens a pull request or an issue. The wake sends only a flushed batch: one inbox line whose `batch` string is the collapsed critic review, CI, and handoff for that head. `run_end` (posted by that same chat) and `ci_pass` are the only flushes. A new head does not flush a run that is still live. A green head queues critic on `run_end` when the checks are already green, and on `ci_pass` when the run has already ended. A green event seen before `run_end` is not replayed. A head is red only after a required check has failed; a pending check waits, and a red head goes back to the worker with the batch. Before any launch, that chat reads `house/ATTENTION_STATE.md` and does not launch when the day is over pace or weekly burn is at 75% or more, except a hotfix. The card stores `critic_bc`, the critic cloud id for that PR. On a new head the critic chat resumes `critic_bc` and launches a new agent only when the card has no `critic_bc` or that resume is refused. One critic agent per PR. Deep search and thinking still run on a cloud agent: a diff, a fix, code search, tests, every review, and every live pass. Mechanical steps stay on the wake: a head-SHA check, a review-list check, a verdict the cloud already wrote, inbox acks, handoffs, and NOTES lines. One critic verdict per head. The agent wears the suit first (plates, the station ticket, the notes). Never hand-edit the station ticket to record this.
5. Notes after every beat: append to `.xray/state/NOTES.md` right after each real beat (PR opened or pushed, verdict, CI result, merge, deploy, handoff, blocker, cloud agent launch or cancel), with evidence (links, SHAs, comment ids). There is no pre-compact signal, so continuous writes are the only protection.
6. Last, update `.xray/state/NOTES.md`: the intent and the next cut. No secrets: never a key, token or PEM text, only the env var name where a secret lives. Never commit NOTES.md.
7. Turn end is the EXIT trap above. That one close posts `live-inbox <seat> --turn end --tag wake` and then releases the claim. It runs on every exit, including an early return (empty inbox, early return, error) and a crash. The seat does not post it again before the shell exits. Turn end clears the working mark. From the suit folder, run `node node_modules/0xray/scripts/node/auto-reflection-generator.mjs --trigger commit-threshold`. The file lands in `.xray/state/repertoire/feedback`. That command does not run synthesis or confer.
