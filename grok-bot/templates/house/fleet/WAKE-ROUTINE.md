# Seat wake routine (template)

The prompt each seat installs as its webhook-triggered Bifrost inbox wake routine (inbox docs: `house/live/docs/inbox.md` in the repo). Copy the commands below as they are. Replace `<seat>` only. Set `SEAT_KEYS_DIR`, `LIVE_CURSORS` and `LIVE_URL` as folder or URL names only, never a key value. These commands post straight to the board with the seat's own key. The box pusher is not in this routine.

Env first, on every turn, in the same shell as the commands below. `live-inbox` is installed at `$HOME/.burst/bin/live-inbox` (fetched from `house/live/tools/live-inbox` on main); a box that installs it elsewhere sets `LIVE_INBOX_BIN` to that folder (on the forge box, `/home/box/burst-run/bin`). `live-inbox` never guesses: a missing `LIVE_URL`, `SEAT_KEYS_DIR` or `LIVE_CURSORS` exits 2 and names it.

```bash
export PATH="${LIVE_INBOX_BIN:-$HOME/.burst/bin}:$PATH"
export LIVE_URL="${LIVE_URL:-https://burst-live-production.up.railway.app}"
export SEAT_KEYS_DIR="${SEAT_KEYS_DIR:-$HOME/.burst/seat-keys}"
export LIVE_CURSORS="${LIVE_CURSORS:-$HOME/.burst/cursors/<seat>}"
export WAKE_RUN="${WAKE_RUN:-$$}"
live-inbox <seat>
```

0. List the open inbox first with the command above (`live-inbox <seat>`). That export sets `LIVE_URL` and this seat's `LIVE_CURSORS` (`$HOME/.burst/cursors/<seat>`). If there are no lines, or every line repeats a packet already handled (same PR, same head sha, same kind, per NOTES.md), ack each repeated line with `live-inbox <seat> --ack <id>` and stop. No turn start, no STATION or NOTES read, no GitHub check, no summary. Two runs of this seat at once share that claim: the second `live-inbox <seat>` prints nothing, and that run stops the same way. It does not ack the first run's lines, and it posts no turn start. A line that says the seat is still waiting gets one line back, then stop. A new line keeps the full boot read below. On an owner message (a 1:1 or a room), run `live-inbox <seat> --prompt --from blaze` first, and add `--room <name>` when the message was in a room. Then run `live-inbox <seat> --turn start --tag wake`. The step 0 stop does not run step 7.
1. Boot read, every turn (a compaction is a wake). Grok Bot wakes never run `.cursor` hooks, so this step is the boot hook. Read `.xray/state/STATION.md` (the station ticket; never hand-edit it), then `.xray/state/NOTES.md` (the working page), and resume the same role and job. If STATION.md is missing, or its `Fresh:` line names an older package than `node_modules/0xray/package.json`, run `npx 0xray wear` once and read it again; if it's still stale, append one line to NOTES.md and go on. If NOTES.md is missing, create it with `Point:`, `Open:`, `Learned:` and `Next cut:` lines (no secrets) before step 2.
2. Read your inbox: `live-inbox <seat>`. A non-empty read is the work. An empty read with nothing owed is a quiet wake: skip steps 3 to 6 and go straight to step 7. No room post, no NOTES.md write.
3. Handle each open line on its GitHub issue or PR, then ack it: `live-inbox <seat> --ack <id>`. Closed or merged lines are `live-inbox <seat> --ack stale` and then `--apply`. `--upto <id>` acks the stored prefix through that id, including live lines. `--ack all` acks every open line. A missing card, and an old handoff on a live card, stay until `--ack <id>`. When this seat owes a handoff, run `live-inbox <seat> --handoff <to> --pr <owner/repo#n> --kind <ready|critic_fail|live_pass|merge|ci_fail> --sha <head>` and send the printed line as a 1:1. A room post is never a handoff and never a wake: seats may not ack in a room, so a room receipt cannot be relied on.
4. Blaze, 2026-10-19: anything that needs deep search or thinking runs on a cloud agent, however small. That covers reading a diff, judging a fix, code search, tests, every review, and every live pass. Only mechanical steps stay local: a head-SHA check, a review-list check, posting a verdict the cloud already wrote, inbox acks, handoffs, and NOTES lines. One cloud agent per card. Before launching, check the board's `cloud_agent` lines and the CloudAgent list. If an agent for the card is running, or finished with a PR, steer that one instead of launching. One critic verdict per head. The agent wears the suit first (plates, the station ticket, the notes). Never hand-edit the station ticket to record this.
5. Notes after every beat: append to `.xray/state/NOTES.md` right after each real beat (PR opened or pushed, verdict, CI result, merge, deploy, handoff, blocker, cloud agent launch or cancel), with evidence (links, SHAs, comment ids). There is no pre-compact signal, so continuous writes are the only protection.
6. Last, update `.xray/state/NOTES.md`: the intent and the next cut. No secrets: never a key, token or PEM text, only the env var name where a secret lives. Never commit NOTES.md.
7. Turn end: `live-inbox <seat> --turn end --tag wake`. Run it on every exit of the full pass (empty inbox, early return, error), even when you leave before this step. The step 0 stop does not run it.
